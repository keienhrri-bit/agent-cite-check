# 抽取任务书（模板）

适用场景：让 Agent 从文件里捞条目，比如待办、决定、引语、日志里的报错、符合某条规则的行。Agent 交回一张表，每一行都带核对器能打开的出处。

## 给你看的（这部分不发给 Agent）

1. 填好下面任务书里的 `<...>`。「规则」一节一字不改，核对器靠它。
2. 条目有固定标记（`待办：`、`ERROR`、`TODO:`）时，要求 Agent 交一个这个标记的 `count()`。核对器会重算这个数，你就知道一共该有几条，再和表的行数比一比。
3. 发任务书之前，给 Agent 要工作的目录拍一张快照：

   ```
   agent-cite-check snapshot --root <目录> -o before.json
   ```

   `before.json` 放在那个目录外面；放在里面也行，核对时用同一个路径传给 `--before`，核对器会把它排除在改动清单之外。
4. 回报交回后：

   ```
   agent-cite-check <回报.md> --root <目录> --before before.json --writable "out/**"
   ```

   退出码 0 表示出处、数字、文件改动全部对得上。只读摘要。摘要里列出的不符行不能直接用：删掉，或者把清单退回去改一次。

通过不代表的事：有没有漏条（用标记计数来查）、类别分得对不对、摘要写得公不公道。这些是判断，核对器不做。

## 发给 Agent 的任务书

```text
## 目标
从下面的文件里找出所有<哪类条目>，每条一行，交一张表。

## 只读这些文件
- <路径/文件.md>
- <路径/另一个文件.md>

## 产出
交回的内容放进工作目录下新建的 <out/条目表.md>，分三部分。

1. 一张表，列固定为：

| 序号 | 类别 | 责任人 | 概要 | 出处 |
|---|---|---|---|---|

- 类别只写<类别甲>或<类别乙>。<怎么区分。>
- 责任人：原文里点了名的人；没点名的写「无」。
- 概要：自己概括，不超过 30 个字。
- 出处：写成 路径:行号「逐字摘录」（见「规则」）。
- 顺序跟原文一致，同一条不重复列。

2. 一节「数字」：每条一行，写成反引号括起的式子：
- `count(<路径/文件.md>, "<标记>") = N`

3. 一节「文件」：你新建或改动的每个文件一行，新建写 `[+] 路径`，改动写 `[~] 路径`，删除写 `[-] 路径`。

## 规则
- 行号是文件的实际行号，从 1 开始数。
- 摘录照抄那一行的原文，不少于 8 个字；不换说法，不跳过中间的字，不自己加标点。跨两行的摘录写成 路径:12-13。
- 路径照任务书里的写法写。
- 原文没有依据的格子写「无」，不许推测。
- 脚本会逐条核对出处、数字和文件，对不上的行不用。

## 边界
- 不改、不移动、不复制读的文件，只新建 <out/条目表.md> 这一个文件。
- 不下结论、不提建议。拿不准算不算的，写进末尾的「待定」，不进表。
```

- `count(例会记录.md, "待办：") = 5`

[+] out/条目表.md
