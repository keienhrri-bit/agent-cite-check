# 盘点任务书（模板）

适用场景：让 Agent 跨几个文件盘点状态，比如哪些任务做完了、哪些还开着、项目各部分进行到哪一步。每样东西一行，一格可以有好几处出处。

## 给你看的（这部分不发给 Agent）

1. 填好 `<...>`。「规则」一节一字不改。
2. 能自己列出要盘点的对象就列出来（五个待办、四个房间）。列不出时，要一个 `count()` 把总数钉住。
3. 发任务书前拍快照，交回后核对：

   ```
   agent-cite-check snapshot --root <目录> -o before.json
   agent-cite-check <回报.md> --root <目录> --before before.json --writable "out/**"
   ```

4. 只读摘要。出处不符的行不能直接用。

通过不代表的事：「没有记录」是不是真没做（Agent 可能漏读了文件），状态是不是对出处的正确理解。核对器只确认每句摘录确实在 Agent 说的那一行；状态仍然是 Agent 的判断。

## 发给 Agent 的任务书

```text
## 目标
对下面每一项，只根据列出的文件，说明它现在是什么状态。
- <对象 1>
- <对象 2>

## 只读这些文件
- <路径/记录.md>
- <路径/台账.csv>

## 产出
交回的内容放进工作目录下新建的 <out/盘点.md>，分三部分。

1. 一张表，列固定为：

| 编号 | 对象 | 状态 | 出处 |
|---|---|---|---|

- 状态只写 <已完成 | 进行中 | 没有记录> 之一。有一行写明做完了才算「已完成」；提出之后文件里再没提到，写「没有记录」。不推测。
- 出处：状态依据的每一行都写上，每处写成 路径:行号「逐字摘录」，多处之间用「；」隔开。

2. 一节「数字」：每条一行，写成反引号括起的式子，例如 `count(<路径/记录.md>, "<标记>") = N`。

3. 一节「文件」：新建的文件写 `[+] 路径`，改动的写 `[~] 路径`。

## 规则
- 行号是文件的实际行号，从 1 开始数。CSV 的表头是第 1 行。
- 摘录照抄那一行的原文，不少于 8 个字；不换说法，不跳过中间的字，不自己加标点。
- 路径照任务书里的写法写。
- 文件里没有的写「没有记录」，不许推测。
- 脚本会逐条核对出处、数字和文件，对不上的行不用。

## 边界
- 不改、不移动、不复制读的文件，只新建 <out/盘点.md>。
- 不提建议，不解释为什么拖延。
```

## 示例回报

针对 `examples/templates/workspace/` 里的合成文件（目标：`例会记录.md` 里每条待办的状态）。`npm test` 会对它跑核对器。

```markdown
| 编号 | 对象 | 状态 | 出处 |

| 1 | 统计认养住户（苏禾） | 已完成 | 例会记录.md:6「待办：苏禾在周五前统计愿意认养的住户。」；例会记录.md:12「苏禾报了名单，一共 14 户愿意认养。」 |

| 3 | 浇水登记表（林舟） | 没有记录 | 例会记录.md:14「待办：林舟做一张浇水登记表，贴在电梯口。」 |

## 数字
- `count(例会记录.md, "待办：") = 5`
- `rows(采购.csv, 分项=器具) = 3`

## 文件
[+] out/盘点.md
```
